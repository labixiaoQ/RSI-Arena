# Gear Arena 公开协议 v3

v3 用于新的受控运行。它继承 v2 的有界学习、一步后续评测和跨代继承，只修订已确认模型输出无效时的任务语义，并增加公开结果的证据分类。它不是对历史 v1/v2 结果的重新计分。运行目录、账本、旧协议文件、旧试验报告和旧源码快照保持原样；新协议必须使用新的输出目录。

## 一代和一个 episode

候选 harness 为 `H_t=(E_t,I_t)`。搜索时，当前被保留的 `I_t` 根据开发反馈提出一个完整候选 `H'`；固定 I 的 B 臂要求候选 I 与父代 I 完全一致，递归 C 臂允许同时修改 E/I。每代只有一个候选。提案不符合 JSON、字段、长度或固定 I 约束时，该代停止并保留父代，不截断、不补提案、不免费重试。

评测一个 H 时，实际调用其中的 I 一次，得到临时完整 harness。只执行临时 E；临时 I 既不调用，也不继承。学习从固定 P0 开始，经过生成策略、训练对局、基于自身反馈修订策略，再在计分对局评测。临时 E 最多调用 3 次：生成和修订占两次，最多一次修复可插在其中。生成或修订失败时保留上一个可编译策略，全部失败则保留 P0。编译、训练、计分和模型调用都留存凭证。

被 Gear 门控接受的完整 H 才成为下一代父代。下一代提出候选时使用其 I，因此“修改 I”与“继承并实际调用 I”分别记录。一次真实 I 修改或三个受控代次，不足以证明递归带来了性能收益。

## 已知任务失败和未知执行必须分开

| 情况                                                           | v3 行为                                     | 计费与轨迹                                                                                                     |
| -------------------------------------------------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| lookahead 已返回有效 usage，但不是合法 JSON                    | episode 结束，`status=task_failed`，计 0 分 | 结算实测 usage；I 已调用，E 未执行；不编译、不训练、不打计分对局                                               |
| lookahead 缺字段、额外字段、指令为空或单条超过 2048 UTF-8 字节 | 同上                                        | 不截断；即使超长的是待丢弃的临时 I，整个返回值仍无效                                                           |
| HTTP 返回 `finish_reason=length` 且有有效 usage                | 先结算实测 usage，再按输出无效处理          | `AgentReply.invalid_output.reason=truncated`；lookahead 计任务失败，提案终止该代，学习只可使用原有一次修复额度 |
| 网络中断、usage 缺失/不合法、超过预留、凭证丢失                | 异常上抛，运行进入 `needs_recovery`         | 保留预留；不伪造 0 分；禁止自动重发未知请求                                                                    |
| 用户取消、预算或截止时间不足、编译器/裁判基础设施异常          | 保持原有异常/停止流程                       | 不归类为模型格式失败                                                                                           |

已知失败的 episode 具有 `failure.kind=invalid_lookahead`、原因、输出摘要和诊断；`probe`、`policy`、`policy_digest`、`executed_executor` 均为 null，`execution.executor.status=not_executed`。`executed_improver` 是真正收到调用的 I 的摘要。不能用父代 E、P0 或虚构对局填补这一轨迹。

本协议的 0 分是预先定义的任务失败惩罚。失败 episode 保留在开发及最终审计均值的分母内，不能删掉失败项后再平均。Gear 的 evidence 状态可以是 valid，因为这个 0 是合法的协议观测；另用 episode 的 task_failed 表示模型任务失败。原有 `match_score` 字段为兼容保留，v3 将其指标 revision 设为 3，不能与旧 revision 混为同一计分协议。

v1/v2 继续沿用原来的异常语义：非法 lookahead 不转换为 0；HTTP 截断仍由旧版预算调用层抛出并保留预留。v2 的无效提案处理和有界学习修复保持不变。旧试验的事后修订单独保留修订说明，不能倒写成 v3 预先规定的结果。

## 预算和恢复

v2/v3 的完整最坏预算一致。每个 episode 预留最多 1 次 I + 3 次 E、一个 episode，以及训练和计分双方换位对局。每代预先覆盖父代和候选在全部开发/门控任务上的评测，加一次提案。比较试验还要覆盖 B/C 两臂和冻结后的审计。无效输出虽可能提前结束，开跑时不能依赖这种提前结束减少准入额度。

已完成的请求按其真实 usage 结算，未确认请求保守预留。相同 operation ID 及相同输入只读取已确认凭证，不再执行外部工作；未知请求不自动恢复成新请求。改变协议、模型、镜像、预算、实现版本或输入需新建运行，不能修改原账本。

这些本地账本不是公开服务的全局额度。网站仍需按用户/项目进行额度分配、批准、任务领取和凭证认证，避免通过新建目录绕过总额度。

## 新增 MoneCraft 契约

v3 的每个提案、lookahead 和策略学习请求均在原规则后附加如下说明；v1/v2 不注入这一变化：

> `RoundInfo.players` 只包含可见玩家；向量下标不是玩家 ID。必须遍历 `Player`，按 `Player.owner == RoundInfo.player_id` 找到自身，不能使用 `ri.players[player_id]`。没有找到时须安全处理，不能越界访问。

例如座位 1 在只看见自身时，`players` 可能只有一个元素，其下标是 0、owner 是 1。用玩家 ID 1 直接访问向量会越界。矿点信息可见性、方向、占矿时机等其余规则继续来自冻结的游戏契约，不通过网页提示临时改变。

## 公开结果与科研边界

新增结果字段是向后兼容的描述信息：

- `protocol_version`：精确计分协议版本。
- `evidence_kind`：模型 backend 与比赛 backend 的类型，例如 `fixture-model-fixture-matches` 或 `live-model-monecraft-matches`。受控结果不能冒充真实模型结果。
- `same_harness` / `same_improver`：比较两臂冻结后内容摘要是否一致；未完成比较时为 null。
- `difference_attribution`：相同 H 的分差不能归因于 I 进化；不同 H 的 B/C 分差仍是搜索程序对照，不是隔离 E 后的 I 因果贡献。
- `amendment`：新运行默认 null，表示此报告没有附加历史修订记录，不代表已预注册。导入历史修订试验时，发布层必须链接原记录和修订说明，不能覆盖旧账本或重复累计重建凭证费用。
- `metric_scope`：episode 分数定义、无效 lookahead 的计分方式、固定种子/固定对手范围、非正式隐藏测试、描述性统计。
- 审计 `episodes[].status`、`failure_reason`、`task_failures`：保留任务失败与分母信息。

正常 episode 的分数是换位对局积分均值，胜 1、平 0.5、负 0；v3 还包含未打对局的非法 lookahead 惩罚。因此应称“episode 得分”，不能直接称为胜率或 Elo。`paired_C_minus_B` 保留为原始均分之差，不能改名为 RSI 增益。

相同初始 H、相同预算上限和同一评测流程是两臂的公平条件；实际消耗可能因失败或接受路径不同而不同，须一起公开。temperature=0 不意味着策略或得分可完全复现。当前比较器没有自动实施随机化臂顺序、独立搜索重复、模型版本漂移控制或正式隐藏题库，因此不自动输出显著性、I 的因果收益或通用 RSI 优越性。

## 首版公开提交的边界

可先开放结果浏览、指令提交、审核队列和受控 worker 执行。提交内容只允许有界 E/I 文本；模型、endpoint、密钥变量、容器镜像、规则、种子、对手与额度由服务端固定。浏览器不能提交本地执行路径或持有运行密钥。用户指令产生的代码仍是不可信代码。

当前开发容器不是敌意匿名代码执行的生产安全边界。匿名即时执行须先完成原生参考环境、隔离与资源控制的专门验证。公开网站成立不要求先得到正向科研结果，但必须真实展示失败、费用、模型/环境类型和证据限制。

## 验收

1. 非法 JSON、超长 E、超长被丢弃 I、缺字段/额外字段均只调用一次 I，已确认 usage 被结算；新增 E/编译/比赛数均为 0。
2. 同一已知失败恢复时不重新发请求；轨迹明确 E 未执行。
3. 截断且有 usage 的 HTTP 响应进入已知失败；无 usage 或网络中断保留预留，进入 needs_recovery，恢复时不自动重发。
4. v1/v2 的异常与预留行为回归通过；正常 v2/v3 使用相同的学习调用上限和完整代预算。
5. 失败与成功审计 episode 混合时，失败的 0 参与均值；比较两臂都保留同一 H 时，同 H 字段准确，报告不宣称 RSI 收益。

验收使用受控模型与比赛 backend，以及本地 mock HTTP 响应；它验证协议语义，不构成新增真实 MoneCraft/模型实验结果。
