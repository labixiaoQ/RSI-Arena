## 总预算账本

授权上限为 20 次模型请求、150,000 token、40 次对局额度。三个记录目录的消耗全部合计，未重置预算：

- 实际模型请求 **17 次**，服务端报告 token **27,393**。
- 对局额度计入 **27 次**：25 个已确认回执（其中 4 个是后来判定受 SDK 问题影响的编译失败），另 2 次无完整结果的旧尝试保留预留。它们不是 27 局有效对局。
- 控制器调用共 19 次，其中 2 次只读取已确认模型响应，没有新 API 请求。
- 本次有效实验单独消耗 5 次请求、7,662 token、8 局；其余属于故障定位与已撤回评分的试验。

原计划两代。SDK 修复消耗了一部分额度，最终完成一代有效评测。剩余 3 次模型请求少于另一代开发评测至少需要的 5 次，因此停止，不提高上限。预算明细在有效实验目录的 `authorization-budget.json`。

## 发现并修复的问题

第一份记录 `deepseek-20261111` 的策略调用了公开 SDK 的 `in_range` 等函数，但选手共享库没有链接 `sdk.cc`。加载失败后裁判留下不完整回放。该次未产生有效评分，2 次确认模型响应及其消耗保留。

第二份记录 `deepseek-sdk-fixed-20261111` 复用了前两个确认响应，但另一策略引用 SDK 声明的 `PLAYER_NUM` 时暴露了全局量未导出问题，合法 SDK 调用被错误判为编译失败。发现后立即停止并撤回该记录的全部性能结论，账本保持原样。

最终适配器链接 SDK 函数和 Position 运算符，并在独立选手库中提供固定 fight 模式的 `PLAYER_NUM=2`、`MINE_NUM=6`，同时核对裁判的初始数量。启用严格链接，缺失符号在编译时失败。裁判和游戏规则没有改动。完整 SDK 检查覆盖此前生成的五个策略、全部这些 SDK 导出，以及故意缺失符号的反例；检查没有新增模型调用或对局。

## 验证与边界

21 项 Arena/模型接口/续跑测试通过，加上此前通过的 33 项 Gear 控制器和目标测试，共 54 项。类型、格式、安装后的公共接口与打包文件检查通过。恢复有效实验时将模型和游戏接口设置为“调用即报错”，仍能得到完全相同的结果，新增请求和对局均为 0。

本次只测两个固定对手和一个开发 seed，且是 Mac/Colima/Rosetta 开发运行配置。它验证了真实请求、一步后续评测、拒绝与预算控制流程；不支持自主 RSI 收益、泛化能力、正式榜单表现或模型权重演化的结论。
