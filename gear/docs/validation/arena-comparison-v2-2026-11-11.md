# Gear × MoneCraft v2：真实模型对照报告

日期：2026-11-11。模型为 DeepSeek `deepseek-flash`，固定温度 0、最大输出 4096 token，使用用户明确批准的新增额度。完整数据和逐局回放摘要见同名 JSON。

**本次没有得到进化 I 带来收益的证据。** B 的有效候选未提升开发分；C 的候选 E 指令超长，未获准进入评测。两组最终保留的是同一个初始 H。最终均分虽然不同，但这个差异来自相同 H 的重复运行，不能归因于 I 的进化。

## 结果

| 项目 | B：固定 I | C：允许 E/I 进化 |

| 初始 H | 相同 | 相同 |
| 锚点开发分 | 0.25 | 0.25 |

| 候选开发分 | 0.25 | 未评测：候选无效 |

| 最终 seed 31 | 0.375 | 0.375 |
| 最终 seed 47 | 0.375 | 0.625 |
| 最终均分 | **0.375** | **0.500** |

双方冻结 H 的摘要完全相同；原始均分差为 0.125。temperature=0 没有使本次重复调用产生完全相同的策略及成绩。因此不能把“标记为 C 的组分数更高”写成“递归 RSI 提升了 12.5 个百分点”。

每个最终 seed 都从同一 P0 重新执行一层 I 和 E 学习，E 使用训练 seed 1 的两局换位反馈，再在该最终 seed 上与停留策略、公开样例两个对手换位评分。最终评测未使用开发记忆，结果未回流搜索。

## 运行中发现的问题与修订

首版对无效 harness 提案会抛出运行错误，导致 C 在提案之后停止。本次停止时已确认 11 次模型请求、36,740 token、18 局，没有不明预留。

没有放宽 2048 字节限制，没有截断模型指令，也没有重新请求一个更好的提案。修订后的适配器把已确认、但违反 harness 契约的输出记录为失败；固定调度器停止本代，让 Gear 保留并导出父代。传输失败和未确认消耗仍进入恢复状态，不能伪装为无效候选。

为了不修改原始记录，本次保留了原 C 的失败账本，并将其四条确认模型回复、三条独立编译回执、六条游戏回执按严格输入摘要在本地重放到修订后的控制流程。该重放不调用模型、不重新编译、不重打游戏；Gear 正确导出原始 H。重放账本中的逻辑调用不重复计为真实消耗。之后才对双方冻结的 H 进行已授权的真实最终评测。

因此这是一份**包含明确失败处理修订的探索性试验**，不是预注册确认性实验。B 的有效提案路径和所有已产生的评分未改变；C 的无效提案仍未被评测或接受。

## 目前能支持的结论

工程闭环已经具备游戏契约检查、反馈学习、I 继承与一步评测、候选失败处理、预算、恢复和可追溯对照。真实模型能够生成可编译策略并接收训练反馈，但本次未产生可归因于 I 进化的改进。

策略源码复核发现一个具体错误：部分输出用 `ri.players[me]` 访问自身玩家，而上游 `RoundInfo.players` 只包含可见玩家，应根据 `owner == player_id` 查找。部分策略还使用容易往返振荡的贪心导航。反馈中的移动次数本身不足以证明有效探索或占矿。

进一步研究应先增加重复试验、明确这一 SDK 使用细节，并测试是否能稳定产生有效的新 I，再讨论收益大小。两个最终 seed、固定对手池和 Mac/Rosetta 开发运行环境不支持显著性、跨任务泛化或参考榜单性能结论。网站继续留到实验协议稳定之后。
