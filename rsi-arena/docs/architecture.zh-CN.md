# 首版已实现架构与验收边界

## 目标和协议

评测对象是 H=(E,I)。E 生成和修订策略；I 修改 E，并在递归组允许修改自身。B 固定 I，C 允许继承被接纳的 I。每个候选从统一初始策略执行一步后续学习，再由固定裁判计分。后续学习中的临时 I 不继承，下一代使用正式保留的 H。

首版服务固定一代搜索，随后冻结 H，并在独立审计种子 31、47 上比较。它实现可扩展的递归闭环，但一代公开种子 pilot 不足以证明长期递归收益或 I 的单独因果效应。实际用户任务仍使用固定基础模型；首版不训练模型权重。

v3 区分两类失败：已确认的输出格式错误结算已知消耗并记 0 分，不能从均值分母删除；网络或消耗不明保留预留并停止，进入恢复。无效 lookahead 不执行 E、不编译、不开始比赛。

## Gear 与自建部分

| 模块 | 责任 |
|---|---|
| Gear 原有核心 | 项目、任务、refine、候选选择、journal、导出和恢复 |
| Gear Arena 扩展 | E/I bundle、线性跨代继承、有界学习、固定模型适配、MoneCraft 裁判适配、五维预算预留、B/C 比较与独立审计 |
| 网站 | 登录和所有权、不可变提交、摘要绑定审批、队列与租约、状态和公开 DTO |
| 独立 runner | 固定本机环境、校验批准与源码摘要、心跳和取消、调用 Gear、读取持久账本、净化并上传产物 |
| MoneCraft 上游 | 游戏规则、SDK、初始对手、裁判及真实回放 |

## 数据流

提交 E/I → 服务端固定 manifest → 待审批 → owner 审批精确摘要和额度 → queued → 单个 runner 原子领取 → running → Gear 学习与评测 → 内容摘要上传 R2 → 身份/预算/回放核对 → completed。

不能修改已批准 E/I。修改要新建提交和批准。模型地址、密钥、路径、命令和镜像不接受用户覆盖。runner 默认仅声明受控能力，只有显式启用 live 的机器才领取真实模型任务。

任务存于 D1；批准、租约、单调进度序号和账本快照随任务保存。事件表保留审计摘要。产物按 SHA-256 保存 R2，公开视图只读完成的公开任务；私有任务仅 owner/operator 可见。

## 运行与取消

租约 90 秒、心跳 20 秒。失联立即阻止下一外部动作，runner 中止当前执行；已经发出的模型请求不能靠租约撤回，其未知消耗继续占额。租约失效不自动重新排队。

等待任务取消可即时确认；运行中为 cancel_requested，需 runner 确认实际停止。所有写入使用 lease_id、lease_epoch 和旧进度序号做条件更新，拒绝旧进程及并发过期快照。上传与完成也受租约约束，完成重试必须是完全相同请求。

首版恢复需人工检查原持久目录及账本，没有“一键从零重跑”。无法确认的消耗不会被清零。

## 验收映射

- I 跨代继承：Gear v3 与 runner fixture 回归验证 B 的 I 固定、C 使用被保留的新 I。
- 一步后续评测：同初始策略，generate/compile/train/revise 受限；临时 probe 与继承产物分开。
- 预算：每个外部动作之前预留，未知操作保留，整代计划超过额度不启动。
- 网站：真实 HTTP + 本地 D1/R2 + Gear fixture 跑通提交、审批、领取、心跳、上传、发布读取；无新增真实 API/游戏。
- 对战：42 局已完成真实 MoneCraft 比赛、42,000 回合供浏览；地图按上游 x-major 序列转换为 board[y][x]。
- 研究口径：live/controlled 分开；同 H 不归因 RSI；公开种子不冒充隐藏榜；积分不称 Elo，token 不冒充美元账单。

## 当前服务边界

这是可部署的研究首版：公开浏览、登录提交、人工审批、独立机器执行。运行器可离线，网站展示最近心跳并保留队列。模型密钥只存在独立 runner；未建全自动付费、多人共享资金池、全天候算力或生产恶意代码隔离。任何新的付费试验都需明确批准该次额度。
